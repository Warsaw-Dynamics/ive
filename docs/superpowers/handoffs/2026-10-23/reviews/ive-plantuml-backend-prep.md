## Concrete minimal fork and import plan

1. Vendor the exact pinned `src/` library and its LICENSE and THIRD_PARTY_NOTICES; omit CLI/LSP bins, CLI dependencies, WASM workspace, development benchmarks and filesystem stdlib resources. Preserve a source manifest with original revision, per-file SHA256, original path, imported path, and a separate local-patch ledger. `src` icon tables retain Open Iconic MIT, Bootstrap Icons MIT, and Material Icons Apache-2.0 notices. No JVM/JAR, external Graphviz, JavaScript, browser or network renderer enters runtime.
2. Use a library-only manifest with serde, serde_json/preserve_order, yaml-rust2/no defaults, winnow and flate2. Keep package naming clear (`puml` fork or aliased `puml-native`). Import files through an explicit source inventory; do not copy temporary `agent_*` programs from the audit checkout. Prefer tracked source from `git show`/archive of the exact revision when the controller authorizes import, preserving notices and generating checksums.
3. Strongest minimal policy is unconditional resource denial in this private fork, rather than adding a caller-switchable host-I/O policy that the standalone engine never needs. `src/preproc/includes/mod.rs` already separates wasm no-I/O stubs from native resolvers. Adapt the MIT wasm denial functions into target-independent denial implementations; exclude native `paths`, `resolution`, `stdlib` and URL-fetch implementations from the library. Keep include/import syntax recognized so macro-expanded directives fail with a self-contained `E_RESOURCE_DENIED` naming directive/target. All six include/import variants must fail in the internal dispatcher before any environment, path/canonicalize/exists or file operations.
4. Disable stdlib inventory at the internal API as well: `src/stdlib.rs::resolve_local_stdlib_root`, `local_stdlib_inventory` and `inventory_from_root` must error before host probes. Reject `NormalizedDocument::Stdlib` / `@startstdlib` / `@startuml\nstdlib` with the same explanation. NEW finding: `%get_all_stdlib` at `src/preproc/builtins/dispatch.rs:404` calls `local_stdlib_inventory(None)` and bypasses a directive-only guard. Disable this builtin explicitly. Existing unsafe file builtins are rejected; getenv already returns empty. No implicit in-memory icon/stdlib include exception initially: all includes denied means all includes denied, including `<openiconic/...>`.
5. Add an options-preserving render entry point to the fork. Never use upstream `compile_with_options` because it reparses with defaults for actual output. A safe common path preprocesses once with the supplied options, detects specialized family on expanded text, dispatches specialized families there, otherwise calls the crate-private raw AST parser and maps diagnostics through the source map before normalize/render. This avoids duplicate preprocessing and preserves macro-expanded family detection. If retaining the existing ordinary options parser, route specialized sources separately with those same options.
6. Harden every sprite allocation before parsing/rendering: checked positive width/height and product, per-sprite pixel cap, cumulative pixel/output cap, bounded deflate (`take(max + 1)` then reject overflow), and checked packed-dimension calculations. Current `decode_compressed_pixels` uses unbounded `read_to_end` before verifying pixels, and several functions multiply u32 width×height unchecked. Treat SVG sprites as untrusted XML; a bare string emitted inside a group is not sanitized.
7. Apply the shared whole-SVG resource boundary to final PlantUML output. Existing extra XML check alone is insufficient because Merman terminal sanitization runs only for Mermaid. Validate CSS tokens (including escaped URLs/imports), elements, namespace handling, attributes, resource references, nonfinite/excessive dimensions, output size and XML shape. Deny raw active content, events, external hrefs, `xml:base`, SMIL animate/set, foreignObject, image/feImage and arbitrary resource mechanisms initially. Internal fragment references and static path icons can remain. Prefer reusing Merman's public resvg-safe terminal validator if it accepts arbitrary SVG; otherwise implement an explicit allowlist plus the shared CSS guard. Guard before rasterization and SVG export.
8. Expose fixed approximate font metrics honestly. No host text-measurer injection exists in this candidate. Do not populate measurement evidence as though GPUI metrics shaped PlantUML geometry. Change shared `RenderError::InvalidSource` display text from `invalid Mermaid source` to language-neutral text when adding this backend.

Source provenance limitation: root MIT grant plus embedded asset notices justify describing a pinned MIT-labelled candidate; there is no exact upstream Java-module derivation ledger. A source-scanning record and layout algorithm review should accompany import. No GPL PlantUML tree or EPL layout implementation was opened during prep. The only original Java files inspected are from the owner-authorized `/mnt/data/Projects/plantuml-mit/src` tree (generated MIT-edition files can retain older comment text after their MIT preamble). All 28 non-stdlib sample families succeeded through both ordinary AST and convenience APIs. However regex and EBNF SVG differed between those entry points; don't silently use the AST-only path merely because it returns success. Math and ditaa simple probes happened to match, which is not evidence every construct matches. The convenience function currently checks specialization before preprocessing, and uses default options, so the fork's new common entry point should fix both issues.

The engine API returns one SVG. Initially reject multi-page outputs with an explicit unsupported-multipage diagnostic rather than silently dropping later pages. Bound page allocation internally or before render; checking Vec length after all pages are rendered is not a resource bound.

## Limits and isolation decision

Preprocessor caps exist (32 include/call depth, 10,000 while iterations, 100,000 total expansions, 8 MiB expanded output, 64 KiB per macro). They are not a request deadline or total memory budget. Family layout/render routines lack cancellation; running them in a thread then returning timeout leaves work alive.

Minimal viable delivery must use the viewer's same-binary worker process with kill-and-reap on timeout/staleness, bounded pipe request/response, and memory/resource limits where available. The engine itself never spawns processes. Add checkpoints in preprocessing, parse and major normalization/layout loops if claiming cooperative engine deadlines. Source/model/output caps alone cannot substantiate a hard deadline; post-render checks cannot substantiate preallocation memory limits. Preserve the current caller API but document PlantUML's limit guarantees precisely. Native tests with hostile examples should execute in a bounded worker until cancellation instrumentation is verified. Reject nonfinite/excessive source `scale` / sprite dimensions before use, plus final canvas limits before raster allocation.

## Original MIT inventory omissions and narrow next corrections

Inspected original MIT `core/DiagramType.java` and registered factories in `PSystemBuilder.java`, not the GPL tree. Candidate 28 is not the full original inventory. Original registered diagram factories absent as distinct candidate routes include HCL (`@starthcl`), gitlog (`@startgit`), packet (`@startpacketdiag`), flow (`@startflow`), BPM (`@startbpm`), standalone Creole, definition blocks and DOT. Original diagnostic/help/version/license/color/font/icon inventories are separate utility surfaces, not additional diagram compatibility wins; some are intentionally inappropriate to a no-host-resource engine. LaTeX exists in the candidate specialized route but shares its Math family row. Original UML description/composite families span component/deployment/usecase-style behavior and cannot be assumed covered just from those three candidate labels. C4/other stdlib packs remain unavailable while includes are denied.

The exact original MIT source explains two reference limitations: `PSystemBuilder` comments out `ChronologyDiagramFactory`, despite chronology remaining in `DiagramType`; `getTypes` has no ditaa match and the builder does not register a ditaa factory. Therefore current chronology and ditaa probe failures are genuine limitations of this pinned MIT edition, not evidence those languages never exist in PlantUML. The candidate adds `@startarchimate`/`@startsdl` aliases which are not original wrapper kinds; original Archimate is UML description syntax, SDL shapes belong within activity syntax. Candidate chart/wire aliases also diverge from original grammar even though their family names are original.

Future reuse candidates (design possibilities, no implementation/admission claimed): packet fields can lower a bounded original packet grammar into the existing native packet layout/model; HCL data can lower into a JSON/YAML-like data-tree model after a real HCL subset parser; gitlog can reuse native gitgraph geometry after parsing original commit/parent semantics; flow/BPM can reuse graph/activity geometry after preserving their node/edge/group semantics. These require authored original-syntax corpus and explicit lowering, not string substitutions into a Mermaid source with assumed equivalence. DOT must not invoke external Graphviz or import EPL layouts; any future support needs its own audited grammar-to-permissive-graph path and honest feature limits. Standalone Creole could reuse existing native text markup primitives, but resources, rich labels and layout need separate tests. These are later expansion tasks, not an excuse to call the present backend full.
