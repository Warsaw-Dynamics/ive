# Liberation Serif GD text oracles

The `ofl-*.dot` fixtures are IVE-authored; their matching `ofl-*-gd.png` files are developer-only pixel oracles from Graphviz 16.1.0 (`dot -Tpng:gd:gd`). The pinned Linux `dot` binary SHA-256 was `61b78ded6e765b8a73d183360355029e51e5c18f9ba36e870f3cce16ee06ad85`. The isolated fontconfig configuration contained only `web/fonts` and mapped Linux Graphviz's `Times` alias to `Liberation Serif`. An `openat` trace confirmed that GD opened `web/fonts/LiberationSerif-Regular.ttf`, SHA-256 `705903ae1382f0150f115d6f10a30f5b2f3d6ade649c474afe6366c39174fb65`. The font is already bundled under [the SIL Open Font License](../../../../web/fonts/LICENSE).

The tested font size is Graphviz's default 14 points at 96 DPI. Glyph masks use hinted `swash` outlines and libgd 2.3.3's eight-level indexed-color coverage rule. The six original one-node PNG oracles cover lowercase `a`, `b`, `c`, `g`, uppercase `A`, and digit `0`; `ofl-undirected-gd.png` covers the three labeled nodes and their incoming edges. The one-node PNG oracles for `1`, `F`, and `m` also verify libgd's 300-DPI text-span measurement. Tests compare decoded RGB pixels.

The independent `ofl-ascii-62-rgb-sha256.tsv` manifest records dimensions and decoded-RGB SHA-256 for 62 single-character PNGs from the same pinned GD binary and font. Each input uses the documented one-node DOT template; the manifest contains hashes, not glyph pixels. The Rust path admits 60 alphanumeric one-node scenes, excluding `Q` and `y`, and the exact undirected scene, with the pinned font hash, size, attributes, dimensions and routes. The corpus test checks all 60 admitted native outputs against their independent oracle digests and verifies explicit native fallback for `Q` and `y`. Other text continues through SVG rasterization.

In the 62-character alphanumeric survey, the same hinted mask and 300-DPI width calculation matched 60 single-glyph GD oracles exactly. `Q` and `y` each differed by one grayscale coverage step at one pixel. Adjusting the hinted size or a common fractional origin did not close those two scan-conversion differences.

A developer-only FreeType probe used libgd's `FT_LOAD_DEFAULT` and `FT_RENDER_MODE_NORMAL` with the same font, 14-point size and 96-DPI resolution. Its eight-level masks matched all 62 Graphviz GD oracles. Swash and FreeType had identical raw masks for 56 glyphs; six differed slightly in raw alpha, and only `Q` and `y` crossed a GD palette threshold. Their discrepant scene pixels were `(44,38)` and `(40,39)`, respectively. Every hinted FreeType contour point for those glyphs appeared at the same 1/64-pixel coordinates in Swash, and their decomposed outline commands matched at 1/256-pixel precision. Clearing FreeType's high-precision and smart-dropout outline flags left both gray masks unchanged.

An isolated Zeno build tested FreeType's 32-bit slanted-edge reciprocal in place of Zeno's 24-bit reciprocal; a separate probe also expanded quadratic curves with FreeType's fixed-point DDA segment count. Both changes together still matched only 60 of 62 GD palettes, with the same single-pixel `Q` and `y` differences. The remaining gap is in gray scan conversion, not font identity, hinting, text placement, outline coordinates or dropout behavior. Production admission stays narrow. No glyph bitmap from the FreeType probe is embedded in the renderer.

These goldens certify the pinned Linux GD oracle. The same Rust font bytes and raster code run in browser WASM; macOS GD/FreeType with this isolated font configuration has not been independently measured.
