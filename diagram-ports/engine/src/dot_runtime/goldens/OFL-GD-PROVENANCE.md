# Liberation Serif GD text oracles

The `ofl-*.dot` fixtures are IVE-authored; their matching `ofl-*-gd.png` files are developer-only pixel oracles from Graphviz 16.1.0 (`dot -Tpng:gd:gd`). The pinned Linux `dot` binary SHA-256 was `61b78ded6e765b8a73d183360355029e51e5c18f9ba36e870f3cce16ee06ad85`. The isolated fontconfig configuration contained only `web/fonts` and mapped Linux Graphviz's `Times` alias to `Liberation Serif`. An `openat` trace confirmed that GD opened `web/fonts/LiberationSerif-Regular.ttf`, SHA-256 `705903ae1382f0150f115d6f10a30f5b2f3d6ade649c474afe6366c39174fb65`. The font is already bundled under [the SIL Open Font License](../../../../web/fonts/LICENSE).

The tested font size is Graphviz's default 14 points at 96 DPI. Glyph masks use hinted `swash` outlines and libgd 2.3.3's eight-level indexed-color coverage rule. The six original one-node PNG oracles cover lowercase `a`, `b`, `c`, `g`, uppercase `A`, and digit `0`; `ofl-undirected-gd.png` covers the three labeled nodes and their incoming edges. The one-node PNG oracles for `1`, `F`, and `m` also verify libgd's 300-DPI text-span measurement. Tests compare decoded RGB pixels.

The independent `ofl-ascii-62-rgb-sha256.tsv` manifest records dimensions and decoded-RGB SHA-256 for 62 single-character PNGs from the same pinned GD binary and font. All 62 inputs were reproduced byte for byte with the final isolated fontconfig configuration, SHA-256 `28e8a2709b9ce02b4c6c352d31a9dafe98b69c6b884a060c99107b0b98a2b447`. Each input uses the documented one-node DOT template; the manifest contains hashes, not glyph pixels. The Rust path admits all 62 alphanumeric one-node scenes and the exact undirected scene, with the pinned font hash, size, attributes, dimensions and routes. The corpus test checks every admitted native output against its independent oracle digest. Other text continues through SVG rasterization.

The initial hinted mask and 300-DPI width calculation matched 60 of 62 single-glyph GD oracles. `Q` and `y` each differed by one grayscale coverage step at one pixel. Adjusting the hinted size, a common fractional origin, Zeno's slanted-edge reciprocal precision, or quadratic flattening did not close those differences.

A developer-only FreeType probe used libgd's `FT_LOAD_DEFAULT` and `FT_RENDER_MODE_NORMAL` with the same font, 14-point size and 96-DPI resolution. Its eight-level masks matched all 62 Graphviz GD oracles. An independently compiled standalone [FreeType 2.13.2 gray raster](https://raw.githubusercontent.com/freetype/freetype/VER-2-13-2/src/smooth/ftgrays.c) also matched all 62 system FreeType masks byte for byte. The original Rust masks matched 56 raw masks and 60 GD palettes. The discrepant `Q` and `y` scene pixels were `(44,38)` and `(40,39)`, respectively.

Tracing the standalone raster showed that FreeType translates the 26.6 hinted outline to the bitmap origin before rounding an implied midpoint between consecutive off-curve controls. Swash rounds before translation. For negative half-integer y coordinates, integer division toward zero changes the result after translation; two `Q` joins and two `y` joins moved by 1/64 pixel. The Rust path now recomputes only detected implied midpoints in the bitmap coordinate space. An isolated probe then matched 61 raw FreeType masks and all 62 GD palettes. No glyph bitmap from the FreeType probe is embedded in the renderer.

These goldens certify the pinned Linux GD oracle. The same Rust font bytes and raster code run in browser WASM; macOS GD/FreeType with this isolated font configuration has not been independently measured.
