# Definition parser admission

This proof covers only `parser/grammar/definition.lalrpop` and its mechanically generated LALRPOP 0.23.2 output, whose exact grammar/generated SHA256 values are retained in `generated/manifest.json`. Changes to this grammar or generator require renewed inspection of this proof and `context::DEFINITION_ADMISSION`; admission for future grammars must be established separately.

The lexer emits independent directive, horizontal-trivia, identifier and punctuation primitives without checking token positions, declaration order or mandatory separators. A lexical name-tail mode owns the remaining raw literal after any identifier and horizontal trivia, even in an otherwise malformed header. Thus `!defineWHO World`, repeated directives and leading identifiers produce token streams that the generated production rejects. Leading trivia preserves Rust `trim_start` whitespace, including carriage returns, within the physical newline boundary; RHS edges trim ASCII space/tab only. The lexer retains at most one borrowed token per source byte. Token-buffer capacity doubles from four; before each growth/append it checks source-derived retained-byte/count bounds, charges token/copy work and checks cancellation, then uses fallible exact reservation. The actual retained capacity is passed into parser admission. No statement is forwarded to a prior syntax parser.

The inspected seven-state table has only five positive shift transitions (0→2→3→4→5→6). All token-lookahead reductions are absent. At EOF state6 performs the five-symbol definition reduction, returning to state1, which performs the accepting start reduction. Generated location helper reductions exist in emitted functions but no reachable table entry invokes them. There is no nullable recursive cycle. `uses_error_recovery()` is false: no dropped-token accumulation or recovery model is possible. Success uses at most six live states and five symbols; the exact runtime starts with `vec![start_state]` and `vec![]`. Rust vector growth for the concrete i8 state and nonzero symbol types stays within eight state and eight symbol slots, including that initial fixed allocation.

Failure diagnostics call `__expected_tokens_from_states`: at most five terminal probes, each copying at most six states and simulating at most two reductions. The added punctuation terminal has no shifting transition. The copy is dropped between probes; five bounded terminal strings and eight String-vector slots (including vector growth) are admitted conservatively. The actual table admits at most one expected terminal per state; the larger quota safely covers all five. No recursive generated builder or retained syntax list exists. The successful fixed borrowed syntax result carries name/literal and both authored spans. Its action checks cancellation/work before returning; the unchanged evaluator charges definition/model and retained text before copying.

Before `DefinitionParser::parse` can allocate, admission checks thirty-five stack/diagnostic slots against work capacity, a conservative concrete-type byte bound against `source_bytes × 256`, and reserves all five shifts, two reductions, sixteen stack slots, nineteen diagnostic slots and forty diagnostic simulation work units (82 total). The byte bound includes the actual token-buffer capacity, generated symbol payload/tag/location upper bounds, state storage, six-state diagnostic copy, eight String slots and sixteen bytes per possible expected name. Generated state/symbol limits are independent of the buffered malformed header length: no table path shifts more than five tokens, and any other order rejects without recovery. Temporary parser storage does not consume the semantic model-item counter; existing tiny-model definition/origin guards retain their prior outcomes. The source-derived buffer quota and work checkpoints bound even wide malformed headers before generated entry. No input-dependent generated allocation exceeds the checked fixed bounds plus admitted buffer bytes.

Lexical character scans charge/check every256 bytes (at most259 with a UTF-8 character crossing the boundary), including leading and discarded separator trivia. Iterator delivery checks a cloned control on every token and on the attempted EOF delivery, returning a typed `Cancelled` user error rather than fake EOF. With at most five shifts, only one constant transition separates delivery checkpoints. EOF has two bounded reductions; the first action checks control immediately and every256 bytes while validating the at-most16KiB literal. The accepting second reduction performs no allocating or input-length-dependent work. Controlled tests interrupt actual trivia scanning, generated delivery, the first reduction and UTF-8 literal validation; an exhausted iterator also returns cancellation. No worker timeout is used as parser-accounting evidence.

Only the `parse_definition` facade formats structured failures. Offending byte ranges, bounded static categories and exact authored line/byte columns are retained without rendering arbitrary token payloads or unbounded expected-token lists. Cancellation and resource errors remain typed public terminals. Whole-declaration provenance remains unchanged, while eager expansion uses the generated literal span directly. No-rescan, original-cursor, comment/raw ownership and freeze/registry behavior retain their existing tests.
