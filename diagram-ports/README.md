# Native diagram workspace

An independent Rust workspace for a headless diagram engine and a standalone native pgui viewer. IVE's root workspace is unchanged.

PlantUML uses checked-in LALRPOP grammars for supported same-line literal `!define` declarations, paired documents/directive placement, typed family headers, preambles/styles/chrome and the complete supported sequence syntax. Sequence productions build the preserved participant/event model directly from typed declarations, messages/arrows, raw notes, nested frames and lifecycle commands. One shared lexical owner protects authored and expanded comments, quotes and raw payloads; structured failures map expanded byte spans once through the origin document. The immutable evaluator/registry, semantic models, layouts and Creole remain. Other family parsers temporarily receive materialized physical lines pending their syntax migrations. Ordinary builds/renders require no generator. Developer regeneration and read-only checks use an independent pinned closure:

```sh
CARGO_TARGET_DIR=/mnt/data/Projects/ive/target cargo run --locked --offline --manifest-path tools/plantuml-grammar-gen/Cargo.toml -- generate
CARGO_TARGET_DIR=/mnt/data/Projects/ive/target cargo run --locked --offline --manifest-path tools/plantuml-grammar-gen/Cargo.toml -- check
python3 tools/audit-plantuml-generator.py check
python3 -B tools/audit-plantuml-generator.test.py
node tools/parser-baseline.mjs check
```

Generation uses LALRPOP 0.23.2, no default features, explicit empty grammar features and fresh temporary input/output mirrors. `check` byte-compares generated Rust and the deterministic inventory without writing tracked outputs. Never edit or format generated files. The immutable 43-fixture baseline was recorded from the public render API before this cutover; `record` refuses an existing baseline. It retains exact source, family and deterministic SVG hashes, independently of parser internals. [Parser admission evidence](provenance/plantuml-parser-admission.md) documents the actual generated stack/reduction and cancellation bounds.

From this directory:

```sh
cargo test --workspace
cargo clippy --all-targets -- -D warnings
cargo build --release
cargo deny --config ../deny.toml check licenses sources
```

Run the viewer from this directory:

```sh
cargo run -p diagram-viewer                              # built-in flowchart
cargo run -p diagram-viewer -- path/to/diagram.mmd        # selected local file
cargo run -p diagram-viewer -- --example sequence
cargo run -p diagram-viewer -- --language plantuml --example plantuml-sequence
cargo run -p diagram-viewer -- --render input.mmd --output diagram.svg
cargo run -p diagram-viewer -- --background --example pie --capture /tmp/diagram-frame.png
```

The language buttons and scrollable example list are keyboard focusable (Tab/Shift+Tab, Enter/Space). The viewer shows source, render progress/errors, fit and 25–400% zoom. Ctrl+0 fits, Ctrl+1 shows 100%, Ctrl+=/Ctrl+- zoom, and Ctrl+B toggles source. All 37 Mermaid corpus variants and 25 native PlantUML checkpoint examples are available. `.puml`/`.plantuml` files select PlantUML unless `--language` overrides it. Selected source files are read-only regular UTF-8 files; symlinks to regular files work. The source panel previews up to 4,096 lines; the complete bounded source is rendered.

`--render FILE --output FILE.svg` exports SVG with deterministic metrics and initializes no GUI/display server. A failed render leaves an existing output untouched. `--background` opens with `focus: false` and never activates the app. `--capture FILE.png` captures GPUI's real last app frame after success or error, writes PNG off the UI thread, then quits; render/capture failures exit nonzero. This is native scene readback, so another window may cover the viewer. No browser or OS screenshot tool is involved. Test instances store no profile, settings, or user state, and their workers end when the window/app closes.

For build-cache reuse with the parent IVE checkout, set `CARGO_TARGET_DIR=/mnt/data/Projects/ive/target`; the standalone dev profiles match IVE's optimized dependency/dev settings. Both `gpui` and `gpui_platform` are pinned to IVE's pgui revision **f5d5fa2f8f07b0be68442e694d22ed6064609e73**, with `font-kit`, `wayland`, `x11`, and macOS `runtime_shaders` platform features.

Rendering, source reads, native text measurement, SVG parsing and rasterization run in a single background service. There is one active render and one replaceable pending request; changing selection cancels the active worker, and generation checks discard stale render/raster results. Native layout caches and font-resolution diagnostics belong to one engine render; shared native font resources remain reusable. A cancelled callback safely retains its own cache until it finishes, then releases it. The viewer owns one parsed usvg tree for containment and fit/zoom rasterization through resvg, then displays a full-color `img(Arc<RenderImage>)`. Its installed-font, generic-family and emoji selection mirror the pinned pgui renderer with the viewer's empty asset source; no bundled fonts are added. Full-channel pixel comparisons against that renderer cover opaque/translucent colors and installed/generic/missing/emoji font fallback.

The host can enlarge the display canvas to contain actual flattened text paths and bitmap/SVG glyph paint, using the same parsed tree it paints. Composed ancestor/viewBox transforms, visible fills/strokes and opacity are accounted for; only overflowing text sides are rounded outward, while original viewport edges stay unchanged. This contains labels such as the built-in tree's `package.json` without changing node positions or engine metrics. Bitmap glyph bounds may conservatively include transparent borders. The status bar and stderr report expansion dimensions.

Containment has an explicit safe subset: SVG clips, masks, filters or patterns preserve the original canvas. If expansion could expose any non-text paint beyond an original edge, the entire canvas also stays unchanged, with a diagnostic. This conservatively protects intentional connector clipping in every direction; it may retain text clipping in those cases. It is not a general SVG-effects normalizer or a label-to-node fitting algorithm. Deterministic SVG export remains unchanged and may still clip with different installed fonts; this host display correction does not supply DOM bbox metrics or establish browser geometry parity.

Before usvg parsing, host admission bounds SVG input at 16 MiB, XML nodes at 100,000 and XML depth at 128. Iterative parsed-tree inspection bounds visits at 100,000, depth at 128, path points at 1,000,000, and aggregate decoded bitmap pixels at 4,194,304 (each bitmap also at most 4096 per axis). Bounds/transforms must be finite and within 1,000,000 coordinate magnitude/axis length; singular transforms are rejected. Cancellation is checked before/after parsing, throughout inspection, before/after rasterization and during color conversion. Parsing/font loading/resvg itself remains in-process background work with cooperative boundaries, not a new killable hard deadline or an overall host-memory ceiling. The existing independent worker deadline and memory limit do not cover these host stages.

A second bounded traversal before each rasterization includes effect subtrees, pattern/image occurrences and nested SVG glyph images. Every offscreen surface is capped at 4096 per axis / 4,194,304 pixels; cumulative conservative paint/surface work is capped at 67,108,864 pixel operations. It counts transformed paint rectangles, bitmap decode occurrences, full-size SVG-image scratch surfaces, pattern tiles, retained group layers, four surface equivalents per clip/mask and sixteen per filter primitive (plus merge inputs). This can reject complex or large effect diagrams rather than risk oversized allocations; no deduplication is assumed where resvg repaints/redecodes. Filter images (`feImage`), convolution, lighting, displacement, morphology, tile and turbulence filters are explicitly rejected by this bounded display policy. In particular, `feImage` uses a different transform context in resvg, so it is rejected before rasterization rather than applying ordinary subtree bounds to it. Simple supported filters, clips, masks and patterns retain their original paint when within these limits. The portable tiny-PNG tests exercise decode/overdraw bounds; the additional actual Linux emoji integration requires installed Noto Color Emoji.

Logical zoom size is independent of the bounded bitmap resolution: 100% displays the host canvas's logical dimensions, and 200–400% enlarges that geometry even when the raster cap has been reached. Large zoomed diagrams may therefore look softer; they remain scrollable and honestly scaled. Requested logical sizes must be finite, positive and at most 1,000,000 pixels per axis; a request exceeding that scroll/layout bound shows an error rather than silently changing zoom. Device scales must be finite, positive and at most 8; Fit uses logical viewport dimensions before requesting device-scaled pixels.

The host starts its own executable in an internal worker mode; the engine itself still does not spawn processes. A framed stdin/stdout protocol sends source in memory, small JSON configuration/measurement/metadata frames, and raw SVG bytes. It bounds source at **256 KiB**, SVG at **16 MiB**, metadata/error/measurement frames at **64 KiB**, aggregate stdout at SVG limit plus **4 MiB**, stderr at **64 KiB**, and measurement RPCs at **4,096** with **16 KiB** text per call. A watchdog independent of pipe I/O and host callbacks enforces a **10-second hard deadline**, kills failed/cancelled/over-limit workers and reaps them. Stdin/stdout and stderr are drained separately. Unix children receive a **2 GiB address-space ceiling** via `setrlimit` before exec; Linux also sets a parent-death kill signal. Address-space enforcement and abnormal-parent cleanup were verified on Linux; macOS enforcement is not yet verified, and non-Unix platforms currently have no OS memory ceiling. Raster requests are separately capped at **4,096 pixels per axis and 4,194,304 pixels total** before allocation. These process/resource limits are not an OS filesystem/network sandbox; the audited engine API provides that no-I/O boundary.

Interactive text metrics cross the worker boundary through bounded synchronous request/reply frames while the watchdog stays independent. The pgui host actually shapes installed fonts for Merman's unwrapped **Measure**, **ComputedLength**, and **CanvasMeasureTextWidth** operations, using native advance widths and ascent/descent line metrics. It parses CSS family lists, chooses the first installed family (including quoted names), resolves generic sans/serif/monospace to installed native families, and ultimately uses the native system font when none match. Weight and italic style are honored. Requests outside the text/font bounds decline to the deterministic fallback. Specialized SVG ink/bbox, wrapping, offsets and other operations also decline explicitly; they are not mislabeled as native glyph bounds. The status bar reports actual native and fallback call counts: some families request only unsupported operations and therefore use deterministic layout throughout. This is partial native metric support, not browser/upstream geometry parity.

For display, pgui/usvg resolves installed SVG fonts (with its own fallback policy) and converts text to paths when parsing; resvg then rasterizes at bounded sizes. Exported SVG retains its text/font declarations, so another machine can select different fonts. Native layout font fallback and usvg painting fallback can differ, as can the backend's family-specific CSS and browser behavior; deterministic headless export and interactive native metrics can therefore produce different geometry.

`diagram-engine` exposes `render(source, &RenderOptions) -> Result<RenderedDiagram, RenderError>`. Source is already caller-owned text: the engine reads no files, resolves no external resources and runs no subprocesses. Rendering is synchronous and belongs outside the UI thread. Cancellation/deadlines are cooperative; a host requiring a hard deadline must isolate rendering in its own worker process.

```rust
use diagram_engine::{render, RenderOptions};
let diagram = render("flowchart LR\n A[Start] --> B[Finish]", &RenderOptions::default())?;
assert!(diagram.svg.contains("<svg"));
# Ok::<(), diagram_engine::RenderError>(())
```

The backend is Merman **0.9.2 with audited local compatibility patches**, derived from its published sources at commit `8e303a43b548c9e40e73f0bc657925d66e7d4fb5`. Its baseline target is **Mermaid 12.1.0**; local patches implement released 12.2 mindmap depth coloring and coherent SVG usecase/tree font styles, not full 12.2 parity. Only core/render crates are patched; original registry checksums, per-file source hashes, required legal texts and the four-file patch ledger are retained in [vendor/README.md](vendor/README.md). Check them with `node tools/audit-merman.mjs`. Selected features are `all-diagrams`, `svg` and `layout-cytoscape`, with default features disabled. ELK, math/embedded math fonts, system-font discovery, system-clock/random/timezone adapters and binary export are disabled. Merman's optional Node/KaTeX helper is never instantiated or exposed by this adapter.

`mindmap.colorBy: depth` is applied to typed nodes and child edges before layout, using structural depth and an eleven-color cycle. Default/explicit `branch` coloring is unchanged. Generic SVG usecase labels now measure and paint with the effective global/theme font (including authored node overrides); actor and HTML-specific font handling remains separate. Tree SVG now emits the same validated effective CSS family list used for measurement, preserving quoted family names, embedded commas and generic fallbacks. These repairs do not provide the unsupported specialized text/bbox/wrapping metrics or establish browser geometry parity.

Graph layout defaults to Dagre. Source-requested unavailable layouts, including ELK, return an error. Other families retain their native specialized layouts, including COSE/fCOSE for architecture. SVG passes Merman's resvg-safe terminal validation and an additional XML/resource check. The adapter normalizes XML-escaped CSS before CSS processing (fixing usecase output) and gives info's recorded 400×100 canvas a viewBox.

All **37 admitted Mermaid variants** have executable, labelled, positive-size SVG fixtures, also parsed with pgui's usvg 0.46.0: agentflow, architecture, block, C4, class, Cynefin, ER, eventmodeling, flowchart, Gantt, git graph, info, Ishikawa, journey, Kanban, mindmap, packet, pie, quadrant, radar, railroad IR/EBNF/ABNF/PEG, requirement, Sankey, sequence, state, swimlane, timeline, tree view, treemap, usecase, Venn, Wardley, XY chart and ZenUML. This is family admission evidence, not proof of complete syntax support or pixel/geometry parity. The 12.2 differences and default-ELK layout equivalence remain backlog.

## Native PlantUML checkpoint (not a full port)

The files/packetdiag/board/HCL increment adds four dedicated native models. Run `--language plantuml --example plantuml-files`, `plantuml-packetdiag`, `plantuml-board` or `plantuml-hcl` for the actual viewer examples. Exact wrappers are `@startfiles`/`@endfiles`, `@startpacketdiag`/`@endpacketdiag`, `@startboard`/`@endboard` and `@starthcl`/`@endhcl`, with no output filenames or aliases.

Files uses an ordered path trie with a hidden root, reused same-name sibling folders, duplicate final files and distinct file/folder identities. Leading `/` is syntax; `.` and `..` are literal components, without filesystem access or normalization. Trailing `/` declares an empty folder; empty components reject. Exact `<note>`/`</note>` blocks preserve physical rows and attach beside the last file in its parent; after a folder-only path they attach at root. Consecutive notes retain their anchor. Measured preorder rows use native folder/file/folded-note primitives without Twemoji assets or invented connector edges. File names remain literal; notes use the admitted shared Creole subset. Unknown rows and unterminated notes fail explicitly.

Packetdiag accepts either direct field/config rows or one optional canonical `packetdiag {`/`packetdiag{` block with a matching `}`. Fields use `N: Label`, `A-B: Label` or `* Label`, with required whitespace before the label and one optional colon on numeric forms. Inclusive widths are placed in declaration order, so noncontiguous source ranges do not create visual gaps. `*` starts after the preceding declared end (or zero); single-number/auto fields accept positive `[len=N,height=N]`, and explicit ranges accept only height. Unknown, duplicate or malformed attributes and rotation reject. Positive `colwidth`1–999 (default16), `node_height`1–999 (default32), positive `scale_interval`, `scale_direction=ltr|rtl` and `same_height=true|false` affect real geometry. Interval is capped at final configured colwidth; the default is max(1,colwidth/2). Seven-digit endpoints/attributes are bounded. Numeric directives permit one optional semicolon. Fields retain identity across conserved row fragments: at colwidth8, `0-2` then `3-22` splits the latter into5/8/7 bits, correcting the original remainder bug. Full shared-Creole labels set one common measured bit width without ellipsis; all rectangles remain proportional. RTL reverses blocks and tick indices. Equal-height rows promote cells to the maximum; variable-height rows retain individual heights but advance by the maximum, correcting upstream overlap. Continuation/rotation paint and exact upstream scale/theme geometry are not claimed.

Board uses zero-plus activity roots and positive plus-count stage rows. Each release attaches to its nearest prior lower-stage ancestor; stage jumps preserve empty rows. A first child keeps its parent's column, later children follow the preceding subtree, and the next activity starts after the full branch width. Cards reserve measured shared-Creole labels and retain150×70 minima with20-unit pitch gaps; actual dashed stage boundaries span the board. Each root paints once, correcting upstream duplicate paint. No arrows or Kanban lanes are inferred. Orphan releases, excessive plus depth and substantive unsupported command/style/capability forms fail.

HCL is PlantUML's ordered data notation, without Terraform evaluation. Named blocks own ordered fields with `=` or `:`, string scalars, nested objects and arrays of quoted strings/objects. Bare numbers, booleans and null remain strings; duplicate fields append. One block unwraps to its body; several blocks retain textual names (including quoted labels). Duplicate topblock names reject. Whole hash-comment rows are skipped; hashes and resource-looking content inside strings remain data. Backslash consumes the next quoted character (`\\n` becomes `n`); unclosed/multiline quotes and trailing escapes reject. Physical lines remain separators rather than upstream's bare-token concatenation. Bare array members, nested arrays, calls, expressions, interpolation, heredocs and shared style/chrome prefixes fail explicitly; block names such as `title` remain data. Immutable prefix literal constants remain admitted. Typed HCL ownership lowers into genuine ordered data compartments and links from the corresponding field row, preserving empty containers and duplicate rows. HCL labels remain literal. The existing approximate baseline, installed-font fallback and native-layout/pixel-parity limitations apply to all four families.

Chen owns a lexical stack of entity, relationship or composite-attribute IDs, separate from graph containment. Identical attribute short names under different owners remain distinct. Names use Unicode letters/numbers plus underscore/dot; attributes may use a quoted display as alias. Associations outside owner braces require already declared entity/relationship endpoints; parallel/self/cyclic/disconnected graphs retain every link. Matching participation markers are required, without whitespace around the cardinality. Weak/identifying/key/multi/derived decorations, d/o/U subtypes, per-node/link colors, nested entity declarations and broader attribute name/type syntax reject explicitly. Ellipse and diamond links intersect actual boundaries, and measured diamond text fits its interior; native Dagre geometry differs from the original. Run `--language plantuml --example plantuml-chen`.

ArchiMate extends the existing description model with genuinely painted finite `#RRGGBB` fills and the exact LightBlue/LightGreen constants. Display and alias stay separate; aliases use the existing nonempty identifier grammar. Existing package containment and link direction remain description semantics. Every `<<...>>` icon position, sprite/openiconic/image/stdlib macro/include request, ArchiMate package/multiline declaration and invented `@startarchimate` wrapper rejects. No icon, architecture layer/category rule or full ArchiMate validation is inferred from rectangles. Run `--language plantuml --example plantuml-archimate`.

The native frontend translates a documented subset of the authorized **PlantUML MIT 1.2026.9** grammar into distinct typed Rust sequence, UML, state, structured activity, timing, dated Gantt, Salt, nwdiag, Chen, mindmap, WBS and ordered data models and SVG scenes. It does not rewrite PlantUML into Mermaid source. Graphs use checked directed multigraph Dugong/Dagre with charged cooperative work control; states use a separate recursive graph adapter, sequence has native lane/event geometry, activities compose measured tiles with explicit entry/live/dead exit ports, timing uses measured steps/ribbons on a shared numeric axis, Gantt uses a deterministic civil-day schedule and measured date-axis bars/diamonds, Salt uses nested measured tables and distinct controls, nwdiag uses sparse buses and global server boxes, and trees/data use measured native layouts. No backend runs Java, JavaScript, a browser, dot or network code at runtime. Full compatibility, original styling and pixel parity are not claimed.

A sequence `par` frame is a labelled interaction frame, not anchored simultaneous timing.

Literal constants use case-sensitive ASCII word boundaries, including inside quotes and display/data labels. `\\n` immediately before a name is the source boundary exception. A known name touching any non-ASCII scalar is rejected explicitly; unrelated Unicode remains ordinary text. This deliberately narrower policy does not claim equivalence with Java's Unicode Letter/UTF-16-surrogate classification. Unknown names remain literal. For `FIRST SECOND` followed by `SECOND Ready`, `FIRST | SECOND` expands to `SECOND | Ready`; `A B` followed by `B A` produces `B | B`. Quotes in definition values remain characters. Outer ASCII whitespace around the literal is trimmed; quote interiors and raw family payload are preserved.

Definitions cannot be empty, duplicated, outside the wrapper, inside a stylesheet, or after the first family statement. No continuation or physical replacement newline, control characters other than tab, parameter lists, definelong, functions/procedures, assignments, loops, conditions, includes/themes/assets or runtime environment/date/file/network access is admitted. `$name(...)` and `%name(...)` function requests are rejected before evaluation, including inside quoted data. Plain dollar/percent/path/URL-looking text is literal; a `$` before an ordinary constant remains a literal `$`. `##` directly adjoining a matched constant is unsupported concatenation; inert hashes and tree markers retain their family meaning. Expanded source still undergoes complete wrapper, style, family and resource admission; literal values cannot create preprocessing directives or wrapper boundaries.

Retained expanded source plus all frozen values share `source_bytes`; each authored/frozen value is limited to16KiB. Definitions and names consume the existing model/text budget. Compact origin segments plus prior-definition lineage IDs are capped at four times `model_items`, with checked arithmetic; lineage depth is at most `min(32, nesting_depth)`. Direct adjacent source ranges coalesce, including blank lines. Scans, lookups, copies and origin diagnostic searches share the same work/cancellation budget as parsing, layout and serialization. Raw byte ranges, physical lines and one-based UTF-8 byte columns are recorded before comment/quote normalization.

Parser diagnostics keep their authoritative statement locations and append bounded expansion use/definition context. This context does not claim the expansion caused every error on that statement. Late Creole diagnostics are explicitly label-local; complete raw-label matches supply at most eight textual candidates, including inert duplicates, with bounded expansion-use details and omitted counts. Family models still lack exact spans for every late label, and existing YAML nested-flow/quote diagnostics may report line1. This checkpoint does not claim universal precise token diagnostics or full TIM compatibility.

Defaults remain14px sans-serif for existing families and the identical explicit family list `Arial, Liberation Sans, DejaVu Sans, Noto Sans, sans-serif` for tree/data labels. Authored supported font properties override those defaults in both measurement and painting. Title defaults14px bold, legend14px normal, header/footer10px `#888888`. Root font name/color affects chrome too. Generic and unavailable-family fallback can still differ between native measurement and usvg on a particular installation; the actual-paint regression uses installed Liberation Sans and separately preserves tree/data fallback checks. Symbolic marker activation pairs consecutive unescaped occurrences of each kind within a physical or explicit line in bounded linear work; an odd final marker is literal. Activated spans must be nonempty and correctly nested; duplicate nested styles, crossed styles and unclosed recognized tags fail. `~~` is unsupported wave, not strike. Tilde hides only the following `_ - " # ] [ * . / <`; other tildes remain literal, and genuine PUA text is untouched. `\n`, `\\`, `\~` decode once; `\r`, `\l`, `\t`, trailing/unknown backslash escapes fail.
