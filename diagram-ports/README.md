# Native diagram workspace

An independent Rust workspace for a headless diagram engine and a standalone native pgui viewer. IVE's root workspace is unchanged.

From this directory:

```sh
cargo test --workspace
cargo clippy --all-targets -- -D warnings
cargo build --release
cargo deny --config ../deny.toml check licenses sources
```

Run the viewer from this directory:

```sh
cargo run -p diagram-viewer                              # built-in flowchart
cargo run -p diagram-viewer -- path/to/diagram.mmd        # selected local file
cargo run -p diagram-viewer -- --example sequence
cargo run -p diagram-viewer -- --language plantuml --example plantuml-sequence
cargo run -p diagram-viewer -- --render input.mmd --output diagram.svg
cargo run -p diagram-viewer -- --background --example pie --capture /tmp/diagram-frame.png
```

The language buttons and scrollable example list are keyboard focusable (Tab/Shift+Tab, Enter/Space). The viewer shows source, render progress/errors, fit and 25–400% zoom. Ctrl+0 fits, Ctrl+1 shows 100%, Ctrl+=/Ctrl+- zoom, and Ctrl+B toggles source. All 37 Mermaid corpus variants and seven native PlantUML checkpoint examples are available. `.puml`/`.plantuml` files select PlantUML unless `--language` overrides it. Selected source files are read-only regular UTF-8 files; symlinks to regular files work. The source panel previews up to 4,096 lines; the complete bounded source is rendered.

`--render FILE --output FILE.svg` exports SVG with deterministic metrics and initializes no GUI/display server. A failed render leaves an existing output untouched. `--background` opens with `focus: false` and never activates the app. `--capture FILE.png` captures GPUI's real last app frame after success or error, writes PNG off the UI thread, then quits; render/capture failures exit nonzero. This is native scene readback, so another window may cover the viewer. No browser or OS screenshot tool is involved. Test instances store no profile, settings, or user state, and their workers end when the window/app closes.

For build-cache reuse with the parent IVE checkout, set `CARGO_TARGET_DIR=/mnt/data/Projects/ive/target`; the standalone dev profiles match IVE's optimized dependency/dev settings. Both `gpui` and `gpui_platform` are pinned to IVE's pgui revision **f5d5fa2f8f07b0be68442e694d22ed6064609e73**, with `font-kit`, `wayland`, `x11`, and macOS `runtime_shaders` platform features.

Rendering, source reads, native text measurement, SVG parsing and rasterization run in a single background service. There is one active render and one replaceable pending request; changing selection cancels the active worker, and generation checks discard stale render/raster results. Native layout caches and font-resolution diagnostics belong to one engine render; shared native font resources remain reusable. A cancelled callback safely retains its own cache until it finishes, then releases it. The viewer owns one parsed usvg tree for containment and fit/zoom rasterization through resvg, then displays a full-color `img(Arc<RenderImage>)`. Its installed-font, generic-family and emoji selection mirror the pinned pgui renderer with the viewer's empty asset source; no bundled fonts are added. Full-channel pixel comparisons against that renderer cover opaque/translucent colors and installed/generic/missing/emoji font fallback.

The host can enlarge the display canvas to contain actual flattened text paths and bitmap/SVG glyph paint, using the same parsed tree it paints. Composed ancestor/viewBox transforms, visible fills/strokes and opacity are accounted for; only overflowing text sides are rounded outward, while original viewport edges stay unchanged. This contains labels such as the built-in tree's `package.json` without changing node positions or engine metrics. Bitmap glyph bounds may conservatively include transparent borders. The status bar and stderr report expansion dimensions.

Containment has an explicit safe subset: SVG clips, masks, filters or patterns preserve the original canvas. If expansion could expose any non-text paint beyond an original edge, the entire canvas also stays unchanged, with a diagnostic. This conservatively protects intentional connector clipping in every direction; it may retain text clipping in those cases. It is not a general SVG-effects normalizer or a label-to-node fitting algorithm. Deterministic SVG export remains unchanged and may still clip with different installed fonts; this host display correction does not supply DOM bbox metrics or establish browser geometry parity.

Before usvg parsing, host admission bounds SVG input at 16 MiB, XML nodes at 100,000 and XML depth at 128. Iterative parsed-tree inspection bounds visits at 100,000, depth at 128, path points at 1,000,000, and aggregate decoded bitmap pixels at 4,194,304 (each bitmap also at most 4096 per axis). Bounds/transforms must be finite and within 1,000,000 coordinate magnitude/axis length; singular transforms are rejected. Cancellation is checked before/after parsing, throughout inspection, before/after rasterization and during color conversion. Parsing/font loading/resvg itself remains in-process background work with cooperative boundaries, not a new killable hard deadline or an overall host-memory ceiling. The existing independent worker deadline and memory limit do not cover these host stages.

A second bounded traversal before each rasterization includes effect subtrees, pattern/image occurrences and nested SVG glyph images. Every offscreen surface is capped at 4096 per axis / 4,194,304 pixels; cumulative conservative paint/surface work is capped at 67,108,864 pixel operations. It counts transformed paint rectangles, bitmap decode occurrences, full-size SVG-image scratch surfaces, pattern tiles, retained group layers, four surface equivalents per clip/mask and sixteen per filter primitive (plus merge inputs). This can reject complex or large effect diagrams rather than risk oversized allocations; no deduplication is assumed where resvg repaints/redecodes. Filter images (`feImage`), convolution, lighting, displacement, morphology, tile and turbulence filters are explicitly rejected by this bounded display policy. In particular, `feImage` uses a different transform context in resvg, so it is rejected before rasterization rather than applying ordinary subtree bounds to it. Simple supported filters, clips, masks and patterns retain their original paint when within these limits. The portable tiny-PNG tests exercise decode/overdraw bounds; the additional actual Linux emoji integration requires installed Noto Color Emoji.

Logical zoom size is independent of the bounded bitmap resolution: 100% displays the host canvas's logical dimensions, and 200–400% enlarges that geometry even when the raster cap has been reached. Large zoomed diagrams may therefore look softer; they remain scrollable and honestly scaled. Requested logical sizes must be finite, positive and at most 1,000,000 pixels per axis; a request exceeding that scroll/layout bound shows an error rather than silently changing zoom. Device scales must be finite, positive and at most 8; Fit uses logical viewport dimensions before requesting device-scaled pixels.

The host starts its own executable in an internal worker mode; the engine itself still does not spawn processes. A framed stdin/stdout protocol sends source in memory, small JSON configuration/measurement/metadata frames, and raw SVG bytes. It bounds source at **256 KiB**, SVG at **16 MiB**, metadata/error/measurement frames at **64 KiB**, aggregate stdout at SVG limit plus **4 MiB**, stderr at **64 KiB**, and measurement RPCs at **4,096** with **16 KiB** text per call. A watchdog independent of pipe I/O and host callbacks enforces a **10-second hard deadline**, kills failed/cancelled/over-limit workers and reaps them. Stdin/stdout and stderr are drained separately. Unix children receive a **2 GiB address-space ceiling** via `setrlimit` before exec; Linux also sets a parent-death kill signal. Address-space enforcement and abnormal-parent cleanup were verified on Linux; macOS enforcement is not yet verified, and non-Unix platforms currently have no OS memory ceiling. Raster requests are separately capped at **4,096 pixels per axis and 4,194,304 pixels total** before allocation. These process/resource limits are not an OS filesystem/network sandbox; the audited engine API provides that no-I/O boundary.

Interactive text metrics cross the worker boundary through bounded synchronous request/reply frames while the watchdog stays independent. The pgui host actually shapes installed fonts for Merman's unwrapped **Measure**, **ComputedLength**, and **CanvasMeasureTextWidth** operations, using native advance widths and ascent/descent line metrics. It parses CSS family lists, chooses the first installed family (including quoted names), resolves generic sans/serif/monospace to installed native families, and ultimately uses the native system font when none match. Weight and italic style are honored. Requests outside the text/font bounds decline to the deterministic fallback. Specialized SVG ink/bbox, wrapping, offsets and other operations also decline explicitly; they are not mislabeled as native glyph bounds. The status bar reports actual native and fallback call counts: some families request only unsupported operations and therefore use deterministic layout throughout. This is partial native metric support, not browser/upstream geometry parity.

For display, pgui/usvg resolves installed SVG fonts (with its own fallback policy) and converts text to paths when parsing; resvg then rasterizes at bounded sizes. Exported SVG retains its text/font declarations, so another machine can select different fonts. Native layout font fallback and usvg painting fallback can differ, as can the backend's family-specific CSS and browser behavior; deterministic headless export and interactive native metrics can therefore produce different geometry.

`diagram-engine` exposes `render(source, &RenderOptions) -> Result<RenderedDiagram, RenderError>`. Source is already caller-owned text: the engine reads no files, resolves no external resources and runs no subprocesses. Rendering is synchronous and belongs outside the UI thread. Cancellation/deadlines are cooperative; a host requiring a hard deadline must isolate rendering in its own worker process.

```rust
use diagram_engine::{render, RenderOptions};
let diagram = render("flowchart LR\n A[Start] --> B[Finish]", &RenderOptions::default())?;
assert!(diagram.svg.contains("<svg"));
# Ok::<(), diagram_engine::RenderError>(())
```

The backend is Merman **0.9.2 with audited local compatibility patches**, derived from its published sources at commit `8e303a43b548c9e40e73f0bc657925d66e7d4fb5`. Its baseline target is **Mermaid 12.1.0**; local patches implement released 12.2 mindmap depth coloring and coherent SVG usecase/tree font styles, not full 12.2 parity. Only core/render crates are patched; original registry checksums, per-file source hashes, required legal texts and the four-file patch ledger are retained in [vendor/README.md](vendor/README.md). Check them with `node tools/audit-merman.mjs`. Selected features are `all-diagrams`, `svg` and `layout-cytoscape`, with default features disabled. ELK, math/embedded math fonts, system-font discovery, system-clock/random/timezone adapters and binary export are disabled. Merman's optional Node/KaTeX helper is never instantiated or exposed by this adapter.

`mindmap.colorBy: depth` is applied to typed nodes and child edges before layout, using structural depth and an eleven-color cycle. Default/explicit `branch` coloring is unchanged. Generic SVG usecase labels now measure and paint with the effective global/theme font (including authored node overrides); actor and HTML-specific font handling remains separate. Tree SVG now emits the same validated effective CSS family list used for measurement, preserving quoted family names, embedded commas and generic fallbacks. These repairs do not provide the unsupported specialized text/bbox/wrapping metrics or establish browser geometry parity.

Graph layout defaults to Dagre. Source-requested unavailable layouts, including ELK, return an error. Other families retain their native specialized layouts, including COSE/fCOSE for architecture. SVG passes Merman's resvg-safe terminal validation and an additional XML/resource check. The adapter normalizes XML-escaped CSS before CSS processing (fixing usecase output) and gives info's recorded 400×100 canvas a viewBox.

All **37 admitted Mermaid variants** have executable, labelled, positive-size SVG fixtures, also parsed with pgui's usvg 0.46.0: agentflow, architecture, block, C4, class, Cynefin, ER, eventmodeling, flowchart, Gantt, git graph, info, Ishikawa, journey, Kanban, mindmap, packet, pie, quadrant, radar, railroad IR/EBNF/ABNF/PEG, requirement, Sankey, sequence, state, swimlane, timeline, tree view, treemap, usecase, Venn, Wardley, XY chart and ZenUML. This is family admission evidence, not proof of complete syntax support or pixel/geometry parity. The 12.2 differences and default-ELK layout equivalence remain backlog.

## Native PlantUML checkpoint (not a full port)

The native frontend translates a documented subset of the authorized **PlantUML MIT 1.2026.9** grammar into distinct typed Rust sequence, UML, state and structured activity models and SVG scenes. It does not rewrite PlantUML into Mermaid source. Graphs use checked directed multigraph Dugong/Dagre with charged cooperative work control; states use a separate recursive graph adapter, sequence has native lane/event geometry, and activities compose measured tiles with explicit entry/live/dead exit ports. No backend runs Java, JavaScript, a browser, dot or network code at runtime. Full compatibility, original styling and pixel parity are not claimed.

| Area | Admitted checkpoint behavior |
| --- | --- |
| Common | One complete `@startuml` block, BOM/CRLF, apostrophe comment lines, block comments, quoted display/alias, Unicode/XML-safe literal text and explicit newlines. Errors identify statement line and column 1. |
| Sequence | Ordered explicit/implicit participant, actor and database lanes; forward/reverse/dashed/open messages, self calls; single-participant left/right/over single/multiline notes; nested group/alt/else/loop/opt/par/break/critical frames; balanced explicit activate/deactivate and create/destroy. |
| Class/object | Class, abstract class, interface, enum, annotation, object; ordered member/slot compartments and visibility text; prefix `{static}` underline and `{abstract}` italic; underlined object headers; package/namespace nesting and scoped aliases. |
| Relations | Parallel/self/cyclic/disconnected edges; inheritance/realization/association/dependency/aggregation/composition ends; labels and quoted endpoint multiplicities; left-to-right or top-to-bottom layout. |
| Description | Explicit actor/usecase/component/database/node/rectangle and package declarations with genuine native shapes and container ownership. Component/deployment/usecase are examples within this shared family, not three independent backends. |
| Graph notes | Named `note "text" as N` with explicit authored links; escaped newlines allowed. |
| State | Named/quoted states and quoted-display aliases; forward/reverse ordinary hyphen arrows and labels; one initial dot and one final bullseye per owning scope; nested composites, forward references and ordered attached descriptions. `{`/`begin` and `}`/`end state`/`endstate` delimit composites. |
| Activity | Distinct start/stop/end shapes; raw multiline `:action;` including interior semicolons, blank rows and relative whitespace; nested if/elseif/else/endif, while/endwhile, repeat/repeat while; fork lanes with synchronizing join or merge; nested groups/partitions. Live branches converge, loop guards retain direction, and stop/end has no fallthrough. |

Unsupported substantive syntax fails explicitly: other wrappers/families; includes/macros/functions/conditionals and all preprocessing directives; pages/title/legend/scale/style/theme/skinparam; links/images/sprites/rich text/math; sequence anchors, attached activation shorthand, autonumber, references, additional participant symbols and bidirectional arrows; graph ports, direction/hidden/together constraints, container-boundary edges, `/role` qualifiers, inline class inheritance, generic types/stereotypes, visibility selectors, mixed class/description declarations, shorthand description symbols, attached/positioned or multiline named graph notes. Duplicate declarations fail rather than applying upstream reordering/reopening rules. Unimplemented escapes fail rather than changing text. A sequence `par` frame is a labelled interaction frame, not anchored simultaneous timing.

The fixed font policy measures and paints 14px sans-serif, including admitted italics and underline. Native advance/line metrics are genuine; baseline placement still uses the documented `font_size / 4.5` descent approximation, not native glyph bounds. Text does not auto-wrap. Dagre routing/spacing, member ordering and simplified symbols differ from original Graphviz/Teoz rendering. Usecase endpoints intersect ellipses; other endpoint routes use measured bounding boxes. No claim of exact complex-edge label collision avoidance or original iconography is made.

State concurrency/history, choice/fork/join stereotypes, ports, styled/directional transitions, qualified declarations and cross-ownership transitions are rejected. Activity swimlanes, switch/break/kill/detach/backward/goto, legacy syntax, next-arrow lane labels, repeat backward-route suffixes, alternate `if ... is ... then` headers and decorated command variants are rejected. Groups require an opening brace. Unknown commands and substantive suffixes fail; they are not implicit actions. Multiline sequence-note bodies also preserve blank rows, whitespace and comment-looking literal text. Family admission stops at structural declarations and does not treat class members or text bodies as new family commands.

Sequence rows reserve each event's occupied height above and below its anchor, including multiline notes and created heads. Compound graphs reserve measured caption space; endpoint labels are measured before layout and placed outside their owning bounds. Canvas extents include negative coordinates. Unsupported rich-text recognition is lexical and bounded; literal angle text, URLs, unmatched punctuation and admitted Creole tilde escapes remain literal rather than enabling styling.

The common limits and hard worker isolation apply unchanged. Additional native guards cap labels at16KiB, measured lines at4,096, geometry at1,000,000 units, and cumulative expanded namespace-key text at `min(8 × source_bytes, svg_bytes)` before construction/cloning. Comment scanning is linear and charges/checkpoints chunks of at most512 bytes plus one UTF-8 character. The bounded SVG writer checks growth before append. Layout, native callbacks and serialization checkpoint cancellation; caches are per render. The terminal resvg-safe pipeline and resource validation are shared with Mermaid.

Source hashes/behavior mappings, exact MIT notice and fresh fixture identities are in [provenance/plantuml-mit-1.2026.9.json](provenance/plantuml-mit-1.2026.9.json). Run `node tools/audit-plantuml.mjs` to compare all selected authorized files with their source-JAR entries; `node --test tools/audit-plantuml.test.mjs tools/audit-merman.test.mjs` checks audit guards. This records a local artifact hash, not an externally authenticated Maven checksum. No rejected candidate code/examples or third-party PlantUML assets were imported. Broader state/activity syntax, tree/data and later inventory stages remain unimplemented.

The retained PlantUML notices credit Arnaud Roques, Hisashi Miyashita for selected declaration/link contributions, and Serge Wenger for selected state/transition contributions. The source audit also verifies verbatim author/contributor metadata, including varied spacing around credit colons.

Default limits are 256 KiB source, 16 MiB SVG, 10,000 model items, depth 64, 5,000,000 layout work units and a 10-second cooperative deadline. The finite upstream interactive profile also bounds model text, SVG elements and expanded SVG tree size/depth. Caller limits are validated against hard maxima; zero or unreasonable values fail. `RenderOptions.control` can be cloned and cancelled; each invocation creates a child operation, so reusing options does not reuse a completed request's deadline.

`RenderOptions.text_measurement` defaults to deterministic approximate metrics. A host can set `TextMeasurementPolicy::host_display` with a named/versioned `HostTextMeasurer` for all four phases (`Layout`, `Wrap`, `SvgBBox`, `ComputedLength`). The request specifies text, style, operation, width and wrap mode. Missing/invalid host answers fall back explicitly and are recorded in `RenderedDiagram.measurement`; callbacks must themselves be bounded. The standalone viewer supplies the partial native adapter described above.

Resource admission checks normalized semantic image/link/style fields and generated SVG resource attributes, with a CSS tokenizer distinguishing actual URL/import functions from literal strings. URLs and words such as `metadata:` in labels or comments remain ordinary text. External images, navigation targets and CSS resources are rejected; fragment references stay local. The unchanged terminal SVG validator also checks relative/encoded resources before output can reach an SVG consumer. Arbitrary source assets need a later explicit in-memory resource design.

Fixtures are adapted from MIT Mermaid documentation; attribution and full upstream/dependency legal texts are in [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md). Lockfile licences do not cover manually translated algorithms/data by themselves: the notices also retain Merman's embedded-source manifests and their legal files.
