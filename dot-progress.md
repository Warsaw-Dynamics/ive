# DOT parity progress

## Target and acceptance

Implement Graphviz 16.1.0 `dot` behavior in Rust, in process, for bounded DOT input and the DOT graphs generated by the diagram engine. Acceptance requires both exact `-Tjson0` geometry/routes and pixel-identical SVG/PNG output on Linux, macOS, and WASM. The pinned source archive in `diagram-ports/vendor/graphviz` is a development reference. The built 16.1.0 helper is a test oracle only; neither desktop nor web rendering may build, link, load, or execute Graphviz. The pinned static helper supports `json0` and SVG but not PNG; the pixel gate needs a controlled SVG rasterizer and platform-specific reference evidence. Its build lacks libexpat, so matching its HTML fallback does not establish parity for expat-enabled HTML tables.

Parity is established by differential tests against the pinned helper, not by visual inspection alone. For each admitted case, compare parsed graph semantics, graph and cluster bounds, node centers and sizes, edge routes and labels, and final SVG/PNG geometry. Pin or explicitly record font metrics and rendering environment for pixel comparisons on each target platform. Reject unsupported DOT constructs explicitly until implemented; a passing test on a subset is not a claim of full parity.

## Pinned source size

Graphviz 16.1.0 has 9,619 physical C/header lines in `lib/dotgen` plus `plugin/dot_layout`. The layout and output path also uses shared code in `lib/common`, `lib/pathplan`, and `lib/cgraph`; those five directories together contain 54,820 physical C/header lines (including blanks and comments). This is a scope measure, not a target Rust line count.
